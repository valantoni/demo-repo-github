📦 Repositorios en GitHub

Página de demo para la clase de control de versiones

Conceptos clave

Repositorio

Carpeta del proyecto con todo su historial de cambios.

Commit

Una "foto" de los archivos en un momento, con un mensaje que explica qué cambió.

Branch (rama)

Línea de trabajo paralela para probar cambios sin romper main.

Pull Request

Propuesta para unir tu rama a main, con revisión del equipo.

Remote

La copia del repo alojada en GitHub (origin).

Fork

Tu propia copia de un repo ajeno para contribuir sin permisos de escritura.

Flujo de trabajo básico

  1. Clonar el repositorio a tu ordenador
    git clone https://github.com/valantoni/demo-repo-github.git
  2. Crear una rama para tu cambio
    git switch -c mi-cambio
  3. Guardar cambios en un commit
    git add . && git commit -m "Describe tu cambio"
  4. Subir la rama a GitHub
    git push -u origin mi-cambio
  5. Abrir un Pull Request en GitHub y pedir revisión
  6. Actualizar tu main local tras el merge
    git switch main && git pull

Ejercicio práctico: ramas y conflictos

En 15 minutos crearás un repo desde cero, trabajarás con dos ramas, provocarás un conflicto, lo resolverás y lo subirás a GitHub. Usa Git Bash en Windows o la terminal en Mac/Linux. Marca cada paso al terminarlo.

  1. Crea un repositorio vacío
    mkdir practica-git && cd practica-git && git init -b main
  2. Haz tu primer commit
    echo "Hola" > saludo.txt && git add saludo.txt && git commit -m "Primer saludo"
    ¿Error "Please tell me who you are"? Git necesita saber quién eres. Ejecuta una sola vez: 
    git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"
  3. Crea una rama y cambia el saludo
    git switch -c ingles && echo "Hello" > saludo.txt && git commit -am "Saludo en inglés"
  4. Vuelve a main y cambia la misma línea
    git switch main && echo "Hola, mundo" > saludo.txt && git commit -am "Saludo más largo"
    Pregunta: ¿qué contiene ahora saludo.txt? ¿Y en la rama ingles? En main pone "Hola, mundo" y en ingles pone "Hello". Cada rama tiene su propia versión del archivo.
  5. Fusiona las ramas y provoca un conflicto
    git merge ingles
    ¿Qué deberías ver? Git avisa de CONFLICT porque las dos ramas cambiaron la misma línea. Abre saludo.txt: 
    <<<<<<< HEAD
Hola, mundo
=======
Hello
>>>>>>> ingles
    Deja el texto que quieras (por ejemplo "Hola, mundo / Hello") y borra las líneas con <<<, === y >>>.
  6. Termina el merge y mira el historial
    git add saludo.txt && git commit -m "Resolver conflicto" && git log --oneline --graph
    Pregunta: ¿cuántos commits hay y por qué el gráfico se divide? Hay 4 commits. El gráfico se separa en dos líneas (una por rama) y se vuelve a unir en el commit del merge.
  7. Súbelo a GitHub: crea un repo vacío llamado practica-git en github.com/new y conecta tu repo local (cambia TU-USUARIO)
    git remote add origin https://github.com/TU-USUARIO/practica-git.git && git push -u origin main
    Reto extra Sube también la rama ingles con git push origin ingles y búscala en GitHub en el selector de ramas. Luego entra en Insights → Network para ver el mismo gráfico que en el paso 6.
